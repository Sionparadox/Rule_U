# 5단계 검색 방식 비교와 100개 게임 지원 점검

2026-10-23. 실제 GMS `text-embedding-3-large` 색인(지문 `bab910f9b2a3551e`, 110게임·2,541청크)을 기준으로 검색 방식 3종을 비교하고 판본별 지원 상태를 점검했다. 전체 게임의 답변 품질이나 공식 출처를 인증한 결과는 아니다.

## 결론

- **지원 판정: 102게임·107판본.** 미지원 8게임은 완료 집계에서 제외하고 DB의 `editions.supported`를 false로 기록했다.
- **기본 검색은 벡터 유사도(`similarity`)를 유지한다.** 하이브리드는 전체 116문항에서 가장 좋았지만, 이번 작업 이전에 작성된 독립 질문 8개에서는 벡터 검색보다 낮았다. 질문 작성 방식의 편향(아래 한계)을 배제할 수 없어 기본값 전환은 보류한다. `SEARCH_MODE=hybrid`로 선택할 수 있다.
- **MMR은 비교 모드로만 제공한다.** 결과 다양성은 가장 높았으나 정답 페이지 적중률이 가장 낮았다.
- **공식 FAQ·정오표 결합 기능은 구현했지만, 결합된 문서는 0건이다.** 현재 117개 문서가 모두 규칙서이며 확인된 FAQ·정오표 관계가 없다.

## 구현

| 항목 | 내용 |
|---|---|
| 동일 청크 집합 | 세 방식 모두 같은 Chroma 컬렉션과 같은 게임·판본·문서 필터를 사용한다. |
| 키워드 검색 | 범위 안 청크 전체에 BM25(k1=1.2, b=0.75)를 적용한다. 한국어 형태소 분석기 대신 어절과 음절 2-gram을 함께 토큰으로 사용한다. |
| 하이브리드 | 벡터 상위 20개와 BM25 상위 20개를 RRF(k=60)로 병합한다. |
| MMR | 벡터 상위 20개 후보에서 λ=0.5로 관련성과 중복을 조정해 5개를 고른다. |
| 설정 | `SEARCH_MODE=similarity|hybrid|mmr`. 이 보고서 시점의 기본값은 `similarity`였고, 이후 [후속 평가](search-quality-followup.md)를 거쳐 `hybrid`로 바뀌었다. 서버 재시작 후 적용된다. |
| FAQ·정오표 | `type=faq|errata` 문서는 `config/document-relations.json`에 `status=verified`, 같은 `edition_id`, 같은 범위의 규칙서를 가리키는 `amends_document_id`가 모두 있을 때만 검색에 포함된다. 포함된 근거에는 수정 관계가 표시되며, 프롬프트는 같은 항목이면 정오표·FAQ를 우선하고 수정 사실을 밝히도록 지시한다. |
| 지원 점검 | `python -m rule_u.stage5 audit`이 판본별로 문서 확보·추출 성공·텍스트 판독 가능·판본 연결·색인 청크 수 일치·근거 확인 질문 통과를 모두 확인한다. 하나라도 실패하면 미지원이다. |

## 근거 확인 질문

- `evals/stage5-grounding-cases.json`: 116문항, 106게임, 판독 가능한 111개 판본 전체를 포함한다. 각 판본에 최소 1문항이 있다.
  - 2단계 독립 질문 8개(`stage2_smoke`)
  - 이번 단계 신규 108개(`stage5_grounding`, 원본은 `evals/stage5-grounding-questions.tsv`). 규칙 청크를 읽고 다른 표현으로 바꿔 쓴 질문이며, 정답 페이지는 해당 청크의 페이지다.
- 정답 페이지 보완: 한 가지 이상의 방식이 놓친 문항은 같은 규칙이 다른 페이지에도 쓰여 있는지 문구를 검색해 확인했다. 그 결과 4문항(사이드, 뤄양의 사람들, 블리츠(anomia), 스시 고 파티! 영문판)에 페이지를 추가했다. 추가 페이지는 모든 방식에 동일하게 적용된다.
- 각 질문은 판본별로 게임·판본 범위를 고정해 평가한다. 다른 게임·판본의 청크는 후보에 포함되지 않는다.

## 검색 비교 결과

전체 116문항, 상위 5개 기준. 상세는 [비교 결과 JSON](./stage5-search-comparison.json)에 있다.

| 방식 | Hit@1 | Hit@3 | Hit@5 | MRR@5 | 평균 고유 페이지 수 | 평균 검색 시간 |
|---|---|---|---|---|---|---|
| similarity (기본) | 0.647 | 0.905 | 0.966 | 0.779 | 3.43 | 0.015초 |
| **hybrid** | **0.707** | **0.983** | **1.000** | **0.843** | 3.50 | 0.032초 |
| mmr | 0.647 | 0.802 | 0.905 | 0.735 | **4.04** | 0.249초 |

질문 출처별 결과:

| 질문 집합 | 방식 | Hit@1 | Hit@5 | MRR@5 |
|---|---|---|---|---|
| 2단계 독립 질문 8개 | similarity | 5/8 | 8/8 | 0.781 |
| | hybrid | 4/8 | 8/8 | 0.708 |
| | mmr | 5/8 | 8/8 | 0.740 |
| 5단계 신규 108개 | similarity | 70/108 | 104/108 | 0.778 |
| | hybrid | 78/108 | 108/108 | 0.853 |
| | mmr | 70/108 | 97/108 | 0.735 |

- 하이브리드는 벡터 검색이 놓친 4문항(숲의 속삭임, 르 아브르, 포션 폭발, 갤러리스트)을 모두 상위 5개 안에 찾았다. "이자", "조수" 같은 구체적인 용어가 정답 청크에 있고 벡터 검색은 같은 주제의 다른 페이지를 먼저 반환한 사례다.
- MMR은 중복 청크를 줄여 고유 페이지 수를 늘렸다. 그러나 정답과 비슷한 청크를 중복으로 보고 밀어내 Hit@5가 떨어졌다. 규칙 질문은 정답이 한 곳에 집중되는 경우가 많아 다양성 이점이 작았다.
- 질문 임베딩: 신규 108문항의 첫 실행 평균 0.919초(외부 호출 포함), 캐시 재실행 116/116 적중·평균 0.002초. 단일 로컬 실행의 측정값이다.

## 핵심 게임 답변 평가

사용자 승인 후 쿠·식스 님트·7원더스 건축가들·카탄의 근거와 질문을 GMS `gpt-6.1-sol`로 보냈다. 게임마다 예외·정보 부족·근거 없음 질문을 1개씩 두었고, BGG 보완 조회는 끄고 규칙서 근거만 평가했다. 코드네임의 같은 유형 질문은 [3단계 결과](./stage3-progress.md)에서 검증했다. 상세는 [답변 평가 JSON](./stage5-answer-evaluation.json)에 있다.

| 유형 | similarity | hybrid |
|---|---|---|
| 예외 (판정 + 정답 페이지 인용) | 3/4 | 3/4 |
| 정보 부족 → 되묻기 | 4/4 | 4/4 |
| 근거 없음 → 유보 | 4/4 | 4/4 |
| 합계 | 11/12 | 11/12 |

- 통과한 예외 답변은 규칙서와 내용이 일치한다. 식스 님트: 벌점 카드는 다시 낼 수 없음. 7원더스 건축가들: 금화로 충당할 수 있으면 건설을 미룰 수 없음. 카탄: 9장이면 4장을 버림.
- **실패: 쿠 "백작 부인 저지 후 암살 비용 반환" 질문.** 두 방식 모두 근거 부족으로 유보했다. 쿠 문서의 4개 청크가 모두 근거로 전달됐고, 그중 하나에 "지불 비용은 돌려받지 못한다"가 있다. 따라서 검색 실패는 아니다. 모델이 직접 유보했는지 응답 검증(인용 번호 불일치 등)에서 거절됐는지는 이번 기록으로 구분할 수 없다. 이후 실행을 위해 평가 도구가 모델 원본 응답을 저장하도록 보완했다.
- 표본이 12문항이라 두 검색 방식의 답변 품질 차이를 판단할 수 없다.

## 지원 점검 결과

상세는 [지원 점검 JSON](./stage5-support-audit.json)에 있다.

| 미지원 게임 | 판본 | 사유 |
|---|---|---|
| 카멜 업 (camel-up) | 2개 모두 | 보드라이프 판본은 글꼴 매핑 오류로 전체 페이지가 깨진 문자로 추출됐다. 사용자 판본은 점수 카드 숫자표만 있고 규칙 본문이 없다. |
| 가지각새 (gajigaksa) | 1개 | 전체 페이지 깨진 문자 |
| 러브레터 (love-letter) | 1개 | 전체 페이지 깨진 문자 |
| 여섯불꽃 (six-fireworks) | 1개 | 전체 페이지 깨진 문자 |
| 숲의 속삭임 / 르 아브르 / 포션 폭발 / 갤러리스트 | 각 1개 | 기본 검색(similarity)에서 근거 확인 질문의 정답 페이지가 상위 5개에 없음 |

- 금지된 섬은 보드라이프 판본이 깨진 문자라 미지원이다. 영문 공식 판본은 통과해 게임 자체는 지원으로 집계한다.
- 깨진 문자 문서 6건은 2단계에서 "추출 성공"으로 집계됐었다. 20자 이상이라는 기존 기준만으로는 글꼴 매핑 오류를 걸러내지 못했다. 이번 점검은 비정상 문자 범위 비율이 50%를 넘거나 글자 비율이 30% 미만인 페이지를 판독 불가로 본다. 판독 불가 페이지가 절반 이상이면 해당 문서를 실패로 처리한다. 다국어 설명서(쿼리도의 그리스어 페이지)나 카드 그림 라벨 일부(도미니언)는 문서 전체를 실패로 만들지 않는다.
- 검색 실패 4게임은 `SEARCH_MODE=hybrid`에서는 모두 통과한다. 지원 판정은 현재 활성 기본 검색 기준으로 보수적으로 기록했다.
- 지원 판정으로 웹 화면에서 107개 판본을 선택할 수 있게 됐다. 이전에는 모든 판본이 `supported=false`였다.

## 한계

- **질문 편향:** 신규 108문항은 규칙 청크를 읽고 작성했다. 표현을 바꿨지만 정답 청크의 용어가 질문에 남아 키워드 검색에 유리할 수 있다. 실제로 독립 질문 8개에서는 하이브리드가 벡터 검색보다 낮았다. 기본값 전환 전에 청크를 보지 않고 작성한 질문이나 실제 사용자 질문으로 재평가해야 한다.
- 정답 라벨은 질문당 1~3페이지다. 다른 페이지에도 같은 내용이 있으면 해당 방식의 점수가 실제보다 낮게 계산될 수 있다. 놓친 문항만 문구 검색으로 보완했다.
- 근거 확인 질문 통과는 "정답 페이지가 검색됨"을 뜻한다. 답변 정확성, 공식 출처, 이용 조건을 확인했다는 뜻은 아니다. 공식 출처를 확인한 문서는 여전히 3건이다.
- 깨진 문자 문서의 복구(다른 추출기·이미지 전사·원문 재확보)는 수행하지 않았다. 현재 102게임으로 100개 기준을 충족해 대체 게임은 추가하지 않았다.

## 재현

API 가상환경 Python으로 저장소 루트에서 실행한다. `compare`는 캐시에 없는 질문만 GMS 임베딩으로 전송한다.

```powershell
python apps/api/tools/build_stage5_cases.py
python -m rule_u.stage5 compare --cases evals/stage5-grounding-cases.json --output data/stage5-compare.json
python -m rule_u.stage5 audit --catalog ../data/games --cases evals/stage5-grounding-cases.json --evaluation data/stage5-compare.json --output data/stage5-audit.json --apply
cd apps/api; python tools/evaluate_stage5_answers.py --live   # 근거·질문을 GMS 채팅으로 전송
```

`--apply` 없이 실행하면 DB를 바꾸지 않고 결과만 기록한다.
