# RAG 미사용·사용 답변 비교 (F2015)

2026-10-23. 같은 질문 8개를 같은 채팅 모델(GMS `gpt-5.4-nano`)에 **RAG 없이**(게임·판본·질문만 전달) 한 번, **RAG로**(규칙서 색인 검색 → 근거 번호를 붙여 생성) 한 번씩 물었다. 정답 여부는 모델의 자체 평가가 아니라, 규칙서 해당 페이지의 원문과 직접 대조해 판정했다.

- 질문: [evals/stage5-core-answer-cases.json](../evals/stage5-core-answer-cases.json)의 규칙 예외 질문 4개와 규칙서에 없는 질문 4개(쿠, 6 nimmt!, 7 원더스 건축가들, 카탄).
- RAG 조건: 하이브리드 검색, BGG 보조 검색 끔(규칙서 근거만 사용).
- RAG 미사용 조건: RAG 프롬프트와 같은 판정 값과 같은 정직성 지시("확실히 모르면 추측하지 말고 insufficient_evidence")를 주고, 답의 출처를 스스로 적게 했다.
- 원본 응답: [rag-comparison.json](rag-comparison.json). 재현: `apps/api`에서 `uv run python tools/evaluate_rag_comparison.py --live`.

## 해석

- **정확성:** 이번 4개 게임은 널리 알려진 게임이라 모델이 규칙 예외를 이미 알고 있었다. 이 표본에서는 RAG가 정답률을 끌어올린 차이가 드러나지 않았다. 덜 알려진 게임이나 판본별 차이가 있는 규칙에서 다시 비교해야 정확성 차이를 판단할 수 있다.
- **근거 제시:** RAG 답변은 4건 모두 정답 페이지를 인용해 사용자가 룰북에서 바로 확인할 수 있었다. RAG 없이 답한 쪽도 "출처"를 적었지만, 실제 문서·페이지와 연결되지 않아 맞는지 확인할 방법이 없다.
- **모르는 것에 대한 대응:** RAG는 규칙서에 없는 질문 4건을 모두 유보했다. RAG 없이 답한 쪽은 같은 정직성 지시를 받고도 1건을 근거 없이 단정했다. 상황 판정 서비스에서는 이런 그럴듯한 단정이 가장 위험하다.

## 한계

- 문항이 8개뿐이고, 같은 질문을 한 번씩만 물었다. 답변 안정성은 [후속 평가](search-quality-followup.md)의 반복 실행 결과를 참고한다.
- 정답 판정은 작성자 한 명이 규칙서 원문과 대조했다.
- 두 조건 모두 같은 모델·같은 판정 값을 썼지만 프롬프트 문장 자체는 다르다(RAG 프롬프트에는 인용 규칙이 추가로 있음).
