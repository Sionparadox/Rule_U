# 처리 시간·캐시·검색 설정 비교 (NF2001, NF2002, F2003~F2006)

2026-10-23. 실제 GMS 채팅(`gpt-5.4-nano`)·임베딩(`text-embedding-3-large`)과 실제 색인(110게임·2,541청크, 하이브리드 검색)으로 측정했다. BGG 보조 검색은 껐다(별도의 호출 간격 5초가 있어 로컬 파이프라인 시간과 섞이지 않게 함).

원본: [latency.json](latency.json), [settings-comparison.json](settings-comparison.json).
재현(`apps/api`): `uv run python tools/measure_latency.py --live`, `uv run python tools/compare_settings.py`.

## 1. 질문 처리 시간 (NF2001)

대표 질문 8개(규칙 예외 4개, 규칙서에 없는 질문 4개)를 각각 두 번 물었다. 첫 번째는 질문 임베딩 캐시를 지운 상태, 두 번째는 캐시를 재사용한 상태다. 단계 시간은 요청 진단 정보(`retrieve_seconds`, `generate_seconds`)에 기록된 값이다.

| 구분 | 전체 p50 | 전체 p95 | 검색 p50 | 검색 p95 | 생성 p50 | 생성 p95 |
| --- | --- | --- | --- | --- | --- | --- |
| 첫 질문 | 4.75초 | 11.14초 | 0.40초 | 0.65초 | 4.45초 | 10.80초 |
| 두 번째 질문 | 4.31초 | 9.02초 | 0.05초 | 0.07초 | 4.25초 | 8.97초 |

- 명세의 잠정 목표(캐시 질문 p95 15초 이내)를 지킨다. 첫 질문도 p95 11.1초다.
- 시간의 대부분은 답변 생성(모델 호출)이다. 캐시는 검색 단계만 줄인다(0.40초 → 0.05초). 답변 자체는 매번 새로 생성한다.
- 규칙 예외 질문(답변과 인용 작성)은 8~11초, 규칙서에 없는 질문(유보)은 3~5초였다.
- 화면에는 처리 단계와 경과 시간이 표시되고, 답변 초안이 실시간으로 나타나 체감 대기는 이보다 짧다.

## 2. 문서 수집 캐시 (F2003·F2004·NF2002)

문서 수집 CLI(`python -m rule_u.discovery discover`)는 프롬프트 1로 검색어를 뽑고, 등록된 공식 출처 후보를 프롬프트 2로 선별한다. 같은 질문을 캐시를 지운 상태와 캐시가 있는 상태로 한 번씩 실행했다.

| 게임 | 질문 | 실행 | 시간 | 캐시 |
| --- | --- | --- | --- | --- |
| 6 nimmt! | 벌점으로 가져간 카드를 다시 낼 수 있나요 | 첫 실행 | 3.83초 | 없음 (프롬프트 1·2 호출) |
| | | 재실행 | 0.01초 | 사용 (외부 호출 없음) |
| 카탄 | 도둑을 옮길 때 자원카드를 빼앗는 규칙 | 첫 실행 | 2.15초 | 없음 (공식 확인 후보가 없어 프롬프트 1만 호출) |
| | | 재실행 | 0.002초 | 사용 |

- **프롬프트 1 검색어(6 nimmt!):** `6 nimmt!`, `6 nimmt! 벌점으로 가져간 카드 재사용 가능 여부`, `6 nimmt! 획득한 벌점 카드와 손패 구분`. 게임명 검색어는 항상 포함한다.
- **선별 결과:** 선택 1건(`젝스님트 한국어판`, 사유 `own_rulebook_required`: 선택 게임 자체 규칙서는 선별 결과와 관계없이 항상 포함). 제외 116건(사유 `scope_mismatch`: 다른 게임·판본 문서).
- 지금 등록된 문서는 판본당 1건이라, 같은 판본 안에서 프롬프트 2가 후보를 걸러내는 사례는 아직 없다. 같은 판본에 FAQ가 함께 등록되어 있을 때 프롬프트 2가 고르지 않은 FAQ는 제외되고, 고르면 선택된다는 점은 `test_discovery_scopes_mandatory_rules_cache_and_invalidation`에서 검증한다(제외 사유 `unverified_external_or_not_selected`).
- 온라인 질문 처리는 이미 확보한 색인만 검색하고, 질문할 때 새 문서를 수집하지 않는다. 수집된 원문은 내용 해시로 재사용한다.

## 3. 청크 크기·중복 길이 (F2005)

이미 추출된 페이지를 세 가지 설정으로 다시 나눈 청크 수다(임베딩 호출 없음). 현재 색인은 1000/200이다.

| 문서 | 페이지 | 500/100 | 1000/200 (현재) | 1500/300 |
| --- | --- | --- | --- | --- |
| 카탄 한국어 규칙서 | 3 | 17 | 9 | 7 |
| 7 원더스 건축가들 한국어 규칙서 | 3 | 9 | 5 | 3 |
| 플레이테 쿠: 기본판 및 종교 개혁 확장 | 1 | 7 | 4 | 3 |
| 젝스님트 한국어판 | 2 | 6 | 3 | 2 |

설정을 바꾸면 청크 수가 달라진다. 청크 설정은 색인 버전 키에 포함되어, 설정을 바꿔 다시 색인하면 새 청크로 바뀐다(`test_ingest_index_retry_hash_and_scope`).

## 4. 근거 수 Top-k (F2006)

같은 질문을 `external_top_k` 3·5·8로 검색한 결과다. 괄호는 정답 페이지다.

| 게임 (정답 쪽) | k=3 | k=5 | k=8 |
| --- | --- | --- | --- |
| 카탄 (3쪽) | 3건: 3, 3, 3쪽 | 5건: 위 3건 + 1, 2쪽 | 8건: 위 5건 + 1, 1, 3쪽 |
| 7 원더스 건축가들 (2쪽) | 3건: 2, 3, 3쪽 | 5건: 위 3건 + 1, 2쪽 | 5건 (문서 청크가 5개뿐) |
| 쿠 (1쪽) | 3건: 1, 1, 1쪽 | 4건 (문서 청크가 4개뿐) | 4건 |
| 6 nimmt! (2쪽) | 3건: 2, 1, 2쪽 | 3건 (문서 청크가 3개뿐) | 3건 |

- k를 늘리면 앞 순위는 그대로 두고 뒤에 근거가 더 붙는다. 문서의 청크 수보다 많이 요청하면 있는 만큼만 반환한다.
- 네 질문 모두 k=3에서 이미 정답 페이지가 1위였다. 기본값 5는 예외 조항이 다른 청크에 나뉘어 있을 때를 위한 여유분이다.
