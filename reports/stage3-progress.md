# 3단계 Q&A·상황 판정 구현 결과

2026-10-22. 백엔드 구현·자동 검증과 사용자 승인 후 실제 GMS 질문 5개의 초기 평가를 완료했다. 3단계 초기 완료 기준을 충족했다. 단일 게임·소규모 표본이며 전체 게임의 품질 검증을 뜻하지 않는다.

## 구현

- LangGraph `retrieve → generate` 두 노드로 연결했다. SQLite 게임 메타데이터·판본·선택 확장·대화 맥락·질문 모드를 전달한다. 기존 검색어 추출·후보 선별 프롬프트는 수집 CLI에 유지하고, 온라인 Q&A는 이미 확보된 색인을 검색한다. 온라인 질문이 새 문서를 수집하지 않는다.
- 검색은 게임·판본·문서 적용 범위를 제한한다. 선택하지 않은 확장을 요구하는 문서를 제외하고 후보 20개에서 문서/청크 중복을 제거해 최대 5개를 사용한다. 질문 임베딩 캐시를 재사용한다. 의미 단위 청킹이나 하이브리드 검색은 추가하지 않았다.
- 답변 프롬프트는 카드·턴 단계 부족 시 되묻기, 문서 미지원·충돌 시 유보를 요구한다. JSON 스키마, 판정 값, 인용 번호와 본문 `[n]`의 일치, 근거 없는 단정 판정을 검사한다. JSON 오류는 최대 2회 시도한다. 의미적 뒷받침 여부 자체는 모델 판단이며 번호 검증이 답변 정확성을 보장하지 않는다.
- 빈 근거는 모델 호출 없이 `insufficient_evidence`, 추가 질문은 `needs_clarification`으로 반환한다. 모델 통신 오류는 요청 실패로 처리하며 근거 부족으로 숨기지 않는다.
- 답변·모드·인용 ID와 원문 버전, 제목, URL, 판본, 페이지, 발췌, 언어·출처 유형·정리 전사 정보를 저장한다. `GET /sources/{citation_id}`는 대화 소유 세션만 조회할 수 있다. 대화 재조회에는 인용 ID가 포함된다. 규칙 지원 인증 여부와 로컬 자료 기반 질의 가능 여부를 구분해 미인증 판본도 질의할 수 있지만, 출처를 공식으로 승격하지 않는다.
- Chroma 재색인은 현재 컬렉션 복사 → 변경분 저장 → ID 집합 확인 → 활성 포인터 파일 원자적 교체로 게시한다. 실패한 임시 버전은 검색에 노출하지 않는다. 기존 reader는 이전 컬렉션을 계속 사용할 수 있다. 이전·실패 컬렉션은 자동 삭제하지 않아 재색인이 반복되면 디스크 사용량이 늘어난다. 색인 CLI는 단일 writer로 실행한다. 기존 `rule_docs`는 포인터가 없을 때 그대로 읽는다.
- 인용 스냅샷 JSON 컬럼 마이그레이션을 작성하고 로컬 DB에 적용했다. OpenAPI·TypeScript 타입을 갱신했다. 화면의 근거 패널·상황 판정 UI는 4단계 범위다.

## 검증

- pytest 41개 통과. 기존 27개에 답변·예외 판정, 되묻기, 근거 없음, 잘못된 인용·JSON, 통신 오류 구분, 판본·확장 격리, 세션 접근, 재시작·원문 변경 후 스냅샷 보존, 일부 색인 배치 실패·성공 후 활성 전환 검사를 추가했다.
- Ruff, Alembic upgrade/check, OpenAPI 타입 생성·TypeScript 검사 통과. Chroma 의존성 deprecation 경고 1개가 있다.
- 기존 실제 110게임·2,541청크 재색인/감사에서 신규 임베딩 0건. 검증 중 외부 임베딩 호출을 명시적으로 차단했다. 기존 실제 색인은 변경되지 않았다.
- 실제 평가 입력: 코드네임 일반 질문·예외 질문 3개, 카드/턴 정보 부족 질문 1개, 대회 상금처럼 문서에 없는 질문 1개. `apps/api/tools/evaluate_stage3.py --live`로 실행한다. 결과는 `data/stage3-live-evaluation.json`에 기록한다.
- 승인 전 제한 환경의 실행은 통신 실패였다. 오류와 근거 부족의 구분을 수정하고 회귀 테스트를 추가했다. 당시 자동 승인 검토의 거절은 사용자의 명시적 전송 승인(“ㄱㄱ”) 후 해소했다. 현재 결과 파일은 승인 후 실제 실행 결과로 교체됐다.

## 실제 GMS 평가 결과

| 질문 | 결과 | 인용 대조 |
|---|---|---|
| 힌트 숫자가 3이면 최대 추리 횟수 | 최대 4회, 정답 유지 조건·오답 종료·자발적 종료 설명 (`conditional`) | 5쪽 일치 |
| 암살자 카드를 고르면 | 선택한 팀 패배로 게임 즉시 종료 (`conditional`) | 5쪽 일치 |
| 힌트 숫자 0 | 관련 단어 회피, +1 제한 무시·정답 유지 시 횟수 무제한 (`allowed`) | 7쪽 일치 |
| 이 카드를 지금 써도 되나요 | 카드·행동·역할·턴 상황 추가 질문 (`needs_clarification`) | 인용 없음 |
| 공식 대회 우승자 상금 | 확인 불가 (`insufficient_evidence`) | 인용 없음 |

- 규칙 답변 3개는 보유 규칙서의 페이지별 추출문과 의미를 대조했다. 인용 번호·문서 ID·청크 ID·발췌문·물리 페이지도 일치한다. 정보 부족과 근거 없음 질문에서 임의 규칙·상금 정보를 만들지 않았다.
- 실제 평가 5개 중 5개가 예상 동작에 부합했다. 암살자 질문의 판정 값은 출처 미확인을 반영한 `conditional`이며, 답변 본문의 패배 결과는 명확하다. DB의 `unverified` 출처 표시를 임의로 공식 인증으로 변경하지 않았다.
- 첫 3개 성공 후 4번째 질문 임베딩에서 `provider_call_failed`가 한 차례 발생했다. 평가 도구에 입력 목록을 대조하는 `--resume` 옵션을 추가해 성공 3개를 재전송하지 않고 이어서 실행했다. 4·5번 성공, 최종 종료 코드 0. API 키·벡터 본문은 기록하지 않았다. 모델 통신의 장기 안정성을 보장하는 평가는 아니다.
- 이번 후속 작업은 실제 평가·평가 도구 재개 옵션·문서 갱신이다. 애플리케이션 코드는 변경하지 않았으며 기존 41개 테스트를 재실행하지 않고 인용 대조와 평가 도구 Ruff 검사를 수행했다.

## 남은 작업

다음은 4단계 화면·근거 패널 연결이다. 전체 110게임의 공식성·이용 조건과 답변 품질 인증은 이번 구현 완료에 포함되지 않는다.

LangGraph 구성은 [공식 StateGraph API](https://reference.langchain.com/python/langgraph/graph/state/StateGraph)의 `compile`·`ainvoke` 인터페이스를 따른다.
